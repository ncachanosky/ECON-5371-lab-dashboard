# ECON-5371 Project Dashboard — Reference Example

This repository is a **worked example** of a Quarto dashboard, built live during the Week 12 lab. Its job is to give you a working reference and a starting template for your own project dashboard — not to be copied as-is, but to be understood, cloned, and adapted.

It uses the VAR system from Lab 4 (`output_gap`, `inflation`, `policy_rate`) purely as sample content. Your own project dashboard will show your own data and your own model.

## What's in this dashboard

**Page 1 — Overview**
- Value boxes: observation count, date range, number of variables
- A time-series plot of all three variables
- A stationarity (ADF) results table
- Value boxes for the chosen lag order and VAR stability check

**Page 2 — Model Results** (tabbed)
- Granger causality results table
- Impulse response functions, with a dropdown to pick which shock to display
- Forecast error variance decomposition

## How to run this yourself

1. Clone the repository:
   ```bash
   git clone https://github.com/ncachanosky/ECON-5371-lab-dashboard.git
   cd ECON-5371-lab-dashboard
   ```
2. Activate your course environment and confirm required packages are installed:
   ```bash
   conda activate econ5371
   pip install -r requirements.txt
   ```
3. Render:
   ```bash
   quarto render dashboard.qmd
   ```
   or preview live while editing:
   ```bash
   quarto preview dashboard.qmd
   ```

`dashboard.html` in this repo is a pre-rendered copy — open it directly in a browser if you just want to see the result without rendering anything yourself.

## Using this as a starting point for your own project

This is exactly where your own dashboard should start:

1. Clone or copy the structure of this repo into your own project repo
2. Replace `data/` with your own dataset
3. Replace the model-fitting code in each cell with your own analysis
4. Keep the layout patterns (value boxes → plot → table/columns → tabbed results) as a starting skeleton, then adjust to fit what you're actually showing
5. Keep `dashboard-theme.scss` as-is if you want the same UTEP branding, or adjust the colors/fonts if your presentation calls for something different

## What this dashboard is built from — key Quarto dashboard concepts

If you're reading `dashboard.qmd` to understand how it works, here's the map:

- `format: dashboard` in the YAML turns any `.qmd` into a dashboard — same authoring experience as every other `.qmd` file this semester
- `##` headings create **rows**; `###` headings nested under a row create **columns**
- A code cell with `#| content: valuebox` becomes a compact stat card
- `#| title: "..."` names a card
- `## Row {.tabset}` turns a row into tabs — but note: **every cell is its own tab by default**. If a tab needs more than one cell, group them under a `###` heading (see the "Impulse Responses" tab for an example)
- `# ` (level-1) headings create separate **pages**, linked from the navbar
- `{ojs}` cells run Observable JavaScript in the browser — no server required — which is what makes the impulse-response dropdown interactive

## Two things worth knowing before you build your own

**Row and column heights must sum to 100%.** If they don't, Quarto squeezes everything to fit rather than raising an error — this is the most common way a dashboard ends up looking cramped. Every time you add a row, re-check that all the heights on that page still add up.

**Value boxes are for short content.** A long string will wrap and can get clipped by the box's height. If a value box looks cut off, shorten what you're displaying rather than trying to resize the box.
